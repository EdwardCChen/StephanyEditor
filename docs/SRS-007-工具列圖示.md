# SRS-007：工具列圖示

| 項目 | 內容 |
|---|---|
| 版本 | 1.0 |
| 狀態 | 已拍板，開發中 |
| 前置 | SRS-001 ~ SRS-006 |

## 1. 背景與問題

工具列上的每顆按鈕直接沿用選單的完整文字——「摺疊 / 展開目前區塊」、
「黏著式欄選取」、「欄位編輯器」——十二顆排開就佔滿整條視窗寬度。
實測（`QToolBar.sizeHint()`，同一組動作、同一個樣式）：

| 顯示方式 | 需要的寬度 |
|---|---|
| 只有文字（原本） | **999 px** |
| 只有圖示 | **451 px** |

視窗預設寬度是 1100 px，所以文字版的工具列幾乎把整條寬度吃光，視窗一旦
縮小就開始把按鈕收進溢出選單。

## 2. 拍板決策

| 編號 | 決策 | 理由 |
|---|---|---|
| **D-01** | 圖示由本專案自己畫成 SVG，不用 `QIcon.fromTheme()`，也不用 `QStyle` 的內建圖示 | `fromTheme()` 是 freedesktop 的圖示主題機制，只有 Linux 有。實測 macOS 上 `QIcon.themeName()` 是空字串，`document-new`／`document-open`／`edit-undo` 等 11 個標準名稱 `hasThemeIcon()` 全部回 False。`QStyle` 的內建圖示三平台都拿得到，但沒有書籤／摺疊／巨集／欄選取這些概念，而且各平台長相差很多——本專案的重點正是三個平台同一套操作 |
| **D-02** | 圖示一律單色，執行時把整張圖當遮罩塗上 `QPalette` 推導的顏色 | 沿用 SRS-003 那條規則：顏色不寫死，一律從 palette 推導。SVG 裡寫死的黑色在深色主題下等於看不見；改成執行時上色，使用者中途切換深淺主題也會跟著變 |
| **D-03** | 工具列只顯示圖示，名稱移到 tooltip，並在名稱後面附上該動作的快速鍵 | 圖示不可能自我解釋，名稱不能就這樣消失。快速鍵順帶附上去，使用者把游標停在按鈕上時就順便學到鍵盤操作 |
| **D-04** | 圖示畫成 24×24 viewBox 的線條稿（stroke 2、圓端），不用實心填色與虛線 | 小尺寸的辨識度。第一版的欄選取圖示用了虛線與半透明的文字列，實際算圖後 24px 下只有 34 個像素是全不透明、186 個是半透明，整顆糊成一團，因此改成實線與左右兩截短線 |
| **D-05** | 找不到圖示檔時回傳空的 `QIcon` | Qt 遇到空圖示會退回顯示文字。少一個圖示只是那顆按鈕變成文字，不會變成一顆看不出用途的空白按鈕 |
| **D-06** | 圖示只用在工具列，選單裡不顯示（`setIconVisibleInMenu(False)`） | macOS 與現在的 GNOME 選單都不放圖示。三個平台長得一樣比「各自符合當地習慣」更重要（同 D-01 的理由） |
| **D-07** | 每個功能一律採用該功能**最通用的既有符號**，不因為「隱喻已經過時」就自己發明 | 實際踩過：存檔本來畫成「箭頭落入承接槽」，理由是磁片早就沒人用過實體了——結果那正是**下載**的通用符號，使用者一看就誤會。磁片的隱喻確實死了，但辨識度是靠慣例累積的，不是靠隱喻是否成立。工具列圖示的唯一任務是讓人一眼認出功能，不是表達設計觀點 |

## 3. 功能需求

| 編號 | 需求 |
|---|---|
| F-TB-01 | 工具列各按鈕以圖示表示，不顯示文字 |
| F-TB-02 | 游標停在按鈕上時顯示動作名稱與快速鍵；原本就有的補充說明要保留 |
| F-TB-03 | 深色與淺色主題下圖示都看得清楚，且使用者中途切換主題時立即跟著變 |
| F-TB-04 | 可勾選的動作（黏著式欄選取、錄製巨集）要看得出目前是開著的 |
| F-TB-05 | 三個平台的工具列長相一致 |

## 4. 業務規則

| 編號 | 規則 |
|---|---|
| **BR-TB-1** | 「哪顆按鈕用哪個圖示」只有一份對應表（`TOOLBAR_LAYOUT`）；測試據此驗證每顆按鈕都有對應的圖示檔，且沒有沒人用的圖示跟著一起裝 |
| **BR-TB-2** | 圖示顏色不得寫死，一律由 `theme.toolbar_icon_color()` 從 palette 推導 |
| **BR-TB-3** | 圖示 SVG 一律 24×24 viewBox，且只能用單色（黑或 none）——彩色圖示會被上色步驟整片塗掉，看起來像壞掉 |

## 5. 非功能需求

| 編號 | 需求 |
|---|---|
| NF-01 | 圖示與工具列底色的對比度須 ≥ 3:1（WCAG 1.4.11 對非文字內容的要求），深淺主題都要成立，且須可由測試驗證 |
| NF-02 | 圖示檔隨 Python 套件一起安裝，deb／.app／Windows 三種打包都要帶得到 |

## 6. 範圍外

- **使用者自訂工具列**（增減按鈕、拖曳排序）：目前的按鈕組合是固定的。
- **圖示主題切換**（讓使用者換一套圖示）：只有一套。
