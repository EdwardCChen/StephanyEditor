# SRS-003：程式碼摺疊

| 項目 | 內容 |
|---|---|
| 版本 | 1.0 |
| 狀態 | 已拍板，開發中 |
| 前置 | SRS-001（欄模式核心）、SRS-002（書籤與巨集） |

## 1. 拍板決策

| 編號 | 決策 | 理由 |
|---|---|---|
| **D-01** | 摺疊範圍用「縮排」與「大括號」兩種啟發式推導，不做語法剖析 | 每支援一種語言就寫一個 parser 的維護成本太高；這兩種啟發式已涵蓋絕大多數檔案，與 Notepad++ 的實際行為相當 |
| **D-02** | 以 `QTextBlock.setVisible()` + `QPlainTextDocumentLayout.requestUpdate()` 實作，不自建虛擬視圖 | 這是 Qt 原生支援的機制，捲軸、選取、搜尋都會自動跟著跳過隱藏行；自建映射層要重寫整套座標換算 |
| **D-03** | 摺疊範圍快取，文件變動時才失效 | 行號欄每次重繪都要知道哪幾行可摺疊，大檔案每次重算會卡頓 |
| **D-04** | 摺疊狀態不隨檔案存檔 | 與書籤一致（SRS-002 D-06），屬「工作階段還原」的範圍 |
| **D-05** | 游標或搜尋結果落在隱藏行時，自動展開到看得見 | 游標消失在看不見的地方、或打字打到看不到的位置，是比「保持摺疊」更嚴重的問題 |

## 2. 功能需求

| 編號 | 需求 | 快速鍵 |
|---|---|---|
| F-FD-01 | 行號欄顯示可摺疊標記（▾ / ▸），點擊切換 | 滑鼠 |
| F-FD-02 | 摺疊 / 展開游標所在的區塊 | `Ctrl`+`Alt`+`F` |
| F-FD-03 | 全部摺疊 | `Alt`+`0` |
| F-FD-04 | 全部展開 | `Alt`+`Shift`+`0` |
| F-FD-05 | 摺疊到第 N 層（保留較外層展開） | `Alt`+`1` ~ `Alt`+`8` |
| F-FD-06 | 摺疊後在標頭行尾顯示「⋯ n 行」提示 | — |
| F-FD-07 | 狀態列顯示目前摺疊的區塊數 | — |

## 3. 業務規則

| 編號 | 規則 |
|---|---|
| **BR-FD-1** | 空白行不切斷縮排區塊，但也不計入區塊結尾 |
| **BR-FD-2** | 摺疊時標頭行本身保持可見，只隱藏其內容 |
| **BR-FD-3** | 巢狀摺疊：展開外層時，內層原本摺疊的區塊維持摺疊 |
| **BR-FD-4** | 文件變動後摺疊範圍重算；已不再是區塊起點的摺疊狀態自動清除 |
| **BR-FD-5** | 跳至行號、尋找、書籤跳轉若落在隱藏行，自動展開（D-05） |
| **BR-FD-6** | 游標不得停留在隱藏行；摺疊後若游標被藏起來，移到標頭行 |
| **BR-FD-7** | 大括號偵測須忽略字串與註解內的括號 |

## 4. 非功能需求

| 編號 | 需求 |
|---|---|
| NF-01 | 摺疊範圍偵測為純函式，不依賴 Qt |
| NF-02 | 範圍偵測為單次線性掃描（O(行數)），不得對每一行重新掃描全檔 |
